SAEM subject-kernel benchmarks ​

This page compares tuned per-subject Metropolis–Hastings (MH) and WarmupHMC NUTS kernels in NLMEEstimation.jl. Each of six subjects has a three-dimensional random effect ηᵢ. Neither kernel proposes an 18-dimensional state for all subjects: MH evaluates six independent proposals in a batch, and NUTS advances six separate chains.

The final comparison uses only configurations selected by the procedure below. “Best” means the best observed median effective sample size (ESS) per elapsed second in the tested grid, subject to zero observed NUTS divergences in both fixed-target and changing-target qualification runs. It is not a global optimum or an estimator-accuracy claim.

Model, target, and environment ​

The Theoph fixture uses the public theophylline concentration data, an oral one-compartment model, additive observation error, and Enzyme derivatives. The first six subjects are sampled at fixed starting population parameters θ = [log(1.57), log(2.75), log(31.5), 0], σ = [log(0.7)], and Ω = diag(0.6², 0.26², 0.14²). Each subject's MCMC target is

Measurements ran on a shared Linux x86-64 host with an AMD Ryzen 9 9950X (16 cores, 32 threads), Julia 1.10.12, one BLAS thread, Enzyme 0.13.215, NLMEEstimation benchmark revision 767effa, WarmupHMC 6cd665de7591dc3024893106f64e72f9e90ad49c (version 0.2.1), and Treebars 7426b9c8dc914d767c28ff22f1f75631f3afc41d. The host is shared, so short wall-clock timings can vary with other work.

What the two kernels do ​

The real MH transition first proposes from each subject's Gaussian prior. The prior proposal density cancels from its acceptance ratio. It then proposes a covariance-scaled random walk and uses the complete-data log density. The package makes each likelihood query for all requested subjects in one batch; acceptance remains subject by subject. These are the proposal and acceptance lines from the transition; the full source also validates model outputs:

julia
proposal = Matrix(prior.cholesky_factor * randn(rng, m, n))
proposed_ℓ = conditional_loglikelihoods(model, subjects, θ, σ, proposal)
for k in 1:n
    if log(rand(rng)) < proposed_ℓ[k] - ℓ[k]
        H[:, k] = proposal[:, k]
        ℓ[k] = proposed_ℓ[k]
    end
end

proposal = H + scale * (prior.cholesky_factor * randn(rng, m, n))
proposed_ℓ = conditional_loglikelihoods(model, subjects, θ, σ, proposal)
for k in 1:n
    logratio = proposed_ℓ[k] - ℓ[k] +
        re_logprior(prior, view(proposal, :, k)) -
        re_logprior(prior, view(H, :, k))
    if log(rand(rng)) < logratio
        H[:, k] = proposal[:, k]
        ℓ[k] = proposed_ℓ[k]
    end
end

The real NUTS target and transition combine the model's conditional η gradient with the analytic Gaussian-prior gradient. Each subject warms once from an initial covariance obtained by inverting its local negative log-posterior Hessian. The selected setting uses the full three-by-three covariance; the default public kernel uses its diagonal. A checkpoint-seeded stream_mcmc call resumes the subject under the current SAEM target:

julia
function LDP.logdensity_and_gradient(target::_SAEMSubjectTarget, η)
    ℓ, g = conditional_loglikelihood_and_gradient(target.model, target.subject,
        target.θ, target.σ, η)
    return ℓ + re_logprior(target.prior, η), g - target.prior.precision * η
end

    options=nuts_options, kernel=nuts)

The fixed-target scripts use the same kernel operations but collect every subject draw for ESS. The SAEM fit consumes one transition per subject per outer iteration; each NUTS transition reopens its stream file.

Tuning and measurement ​

All fixed-target candidates retain 1,600 draws per subject. MH first runs 200 burn-in sweeps and tries six fixed proposal scales (0.25, 0.35, 0.45, 0.6, 0.8, 1.2), plus adaptation to acceptance targets 0.2, 0.3, or 0.4. The broad NUTS grid tries three initial metrics (diagonal Hessian, dense Hessian, prior covariance), warmup draw floors 8 or 20, initial gradient-evaluation budgets 50 or 100, and maximum tree depths 4 or 8, with acceptance target 0.8. Twelve follow-up runs vary the acceptance target over 0.6–0.9 for the top fixed-target NUTS settings. The complete 45-row sweep records every setting and measured score.

The broad sweep uses seeds 2026–2030; seeds 2050–2054 check its provisional choices. An aggressive 0.7 NUTS acceptance target initially scored well, but yielded divergences on later seeds and was not selected. Four MH finalists and six NUTS finalists were then measured on seeds 2060–2069. NUTS finalists also ran a 40-iteration, changing-target SAEM fit on seeds 2080–2084. A NUTS finalist qualified only with zero fixed-target and changing-target divergences and finite fit estimates. The highest-scoring qualified NUTS finalist and highest-scoring MH finalist were compared on untouched seeds 2090–2099.

ESS is the initial-positive-pair estimate in bench/saem_kernels.jl. Each seed's ESS is the median over the 18 subject-by-coordinate traces. The reported ESS and wall time are medians over seeds; ESS/second is the median of each seed's ESS divided by its sampling wall time. ESS is capped at the 1,600 retained draws by this estimator. Wall time includes MH burn-in or NUTS warmup and all retained draws, but excludes Julia compilation, model construction, and ESS calculation. NUTS takes the 1,600 retained draws in one stream_mcmc call per subject for this fixed-target test.

NUTS produced about 10 times the ESS per draw, while MH's observed ESS per second was about 11% higher in the fixed-target experiment. The short SAEM fit was about 216 times faster with MH. NUTS does more work per transition, and this implementation reopens a stream file for every subject at every outer iteration. The fit is a cost and integration check, not an accuracy comparison: 40 SAEM iterations do not establish parameter recovery.

These ESS values apply only to stationary, fixed-population targets. SAEM changes its target across outer iterations, so pooling those positions into one chain and reporting an ESS would be invalid. Also, the fixed-target NUTS script collects draws in one stream call, whereas the actual SAEM fit pays the repeated one-transition resume cost. The comparison is specific to this six-subject, three-effect Theoph model; different dimensions, posterior geometry, models, and longer fits may favor different settings. Some WarmupHMC candidate runs logged a TSVD failure with a successful power-iteration fallback during warmup; the reported divergence counts come from sampler results, not those logs.

Reproduce ​

The source is bench/saem_kernel_tuning.jl and bench/saem_kernel_final.jl. From a clone of NLMEEstimation.jl, develop the package and the two unregistered dependencies in one resolver call, then run the scripts:

sh
git clone --branch dev https://github.com/nsiccha/WarmupHMC.jl.git ../WarmupHMC.jl
git clone --branch main https://github.com/nsiccha/Treebars.jl.git ../Treebars.jl
julia --project=test -e 'using Pkg; Pkg.develop([PackageSpec(path=pwd()), PackageSpec(path="../WarmupHMC.jl"), PackageSpec(path="../Treebars.jl")]); Pkg.instantiate()'
julia --project=test bench/saem_kernel_tuning.jl
julia --project=test bench/saem_kernel_final.jl

For an exact replay, check out the package and dependency SHAs listed above. The scripts print individual candidate scores, the selected settings, final fixed-target results, fit timing, and divergences.

The initial 800-draw exploratory run is retained as historical context. Its untuned settings and three-seed sample do not replace the tuned-kernel comparison above.
