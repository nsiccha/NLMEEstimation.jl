Estimation ​

NLMEEstimation Module
julia
NLMEEstimation

Model-agnostic estimators for nonlinear mixed-effects (NLME) models.

A model is any Julia value for which the protocol functions are implemented (see nsubjects, nlme_layout, and per evaluation_style either conditional_loglikelihood or conditional_loglikelihoods). The package owns the random-effect prior η_i ~ N(0, Ω) and its parameterization (see NLMELayout); the model owns everything else.

Derivatives come from automatic differentiation: a model either implements the derivative methods itself or declares an AD backend through ad_backend. The package promises and tests reverse-mode AD with Enzyme. Second order is optional and only ever per-subject blocks (provides_eta_hessian).

Estimators:

  • empirical_bayes (alias posthoc): per-subject posterior modes (EBEs), by Newton on Hessian blocks or by gradient-only BFGS, at fixed population parameters.

  • focei: population estimation using first-order conditional curvature and a derivative-free outer optimizer.

  • saem: population estimation by MCMC stochastic approximation.

covariance_step gives standard errors of a fit's population coordinates, and marginal_loglikelihood its likelihood, OFV, AIC and BIC (for SAEM, by importance sampling or adaptive Gauss–Hermite quadrature). residual_diagnostics gives PRED, IPRED, IWRES, CWRES and NPDE.

Each of these functions takes progress = nothing: a Treebars node under which it builds its own labelled progress node, or a backend symbol such as :term for a new root. With nothing no node is created. Treebars.request_interrupt! on that node stops saem and focei early with their estimate so far; the other functions raise Treebars.ProgressInterrupted.

Subject modes ​

NLMEEstimation.empirical_bayes Function
julia
empirical_bayes(model, θ, σ, ω; subjects = 1:nsubjects(model), η0 = nothing,
                method = default_ebe_method(model), options = EBEOptions(),
                require_convergence = true, progress = nothing) -> EBEResult

Empirical Bayes estimates (posthoc): for fixed population parameters θ, σ and Ω parameters ω, the per-subject mode

julia
η̂_i = argmax_η  log p(y_i | θ, σ, η) + log N(η | 0, Ω).

All subjects are solved in lockstep: each iteration makes one batched gradient call (conditional_loglikelihoods_and_gradients) for every subject still iterating, plus batched value calls for its trial steps, so a joint-program model pays O(N) per iteration rather than O(N) per subject. Models are never called concurrently.

η0 is the starting point: nothing (zeros), a neta × length(subjects) matrix, one vector per subject, or an earlier EBEResult covering these subjects (warm start). method is NewtonEBE or QuasiNewtonEBE.

Throws an EBEConvergenceError if some subject's mode is not found, unless require_convergence = false, in which case the result records the failure in converged. A non-finite complete-data log-density at the starting point is always an error. A trial point at which the model returns -Inf or throws a DomainError, OverflowError or PosDefException (a point outside its domain) is rejected, and a shorter step is tried.

Evaluating the complete-data log-density f can round off by many ulps of f when f sums terms much larger than itself, such as observations far from zero with a small residual SD. Near a mode, a full step whose predicted increase is below √eps · max(1, |f|) is therefore accepted unless f decreases by more than that. The convergence tests use gradients and Hessian blocks, which stay accurate there.

Modes at kinks

A density that is only piecewise smooth (a running minimum, thresholds ordered by min, a clamp) can have its maximum on a kink, where it is the minimum of smooth pieces and its gradient does not vanish. There every step the method's local model predicts to climb crosses the kink, and the search stops with no step accepted. With options.nonsmooth (the default) such a subject is searched further by gradient sampling with the method's own metric (Burke, Lewis & Overton 2005; Curtis & Que 2015): at each point gradients are sampled within a ball of 0.1 down to 1e-6 prior standard deviations, and the step comes from the combination of them that the method's metric makes smallest, which follows the kinks between the sampled pieces instead of crossing them. Each step makes neta + 1 batched gradient calls for its samples, and Newton one batched Hessian call, while the search lasts.

A point where that search stops is a mode on a kink (result.nonsmooth) when the second-order sufficient condition of the smooth problem max t subject to t ≤ f_i holds there: zero is in the convex hull of the sampled pieces' gradients, and the weighted sum of their Hessians is negative definite along the kinks (on the directions along which all of them change alike). The Hessians are the model's or those of its declared eta_hessian_sparsity; a gradient-only model's are forward differences of its gradients. That check is exact for at most 36 such directions. Last, the density is evaluated 1e-3 prior standard deviations from the point along each coordinate, each sampled gradient and a few random directions, both ways, and a higher point restarts the search. A subject whose search ends on a smooth mode is reported as a smooth mode, and one that ends without either is not converged.

progress is a Treebars node (or a backend symbol such as :term) under which an Empirical Bayes (Newton) or (BFGS) node reports the solver's iteration and how many subjects have converged. Treebars.request_interrupt! on it raises Treebars.ProgressInterrupted at the next iteration.

EBEMethod

Per-subject mode search of empirical_bayes:

  • NewtonEBE: Newton on the η Hessian blocks, needs provides_eta_hessian or a declared eta_hessian_sparsity.

  • QuasiNewtonEBE: BFGS on η gradients only.

source
NLMEEstimation.NewtonEBE Type
julia
NewtonEBE()

Trust-region Newton on the complete-data Hessian blocks. Each step maximizes the local quadratic model of the complete-data log-density over a ball in the standardized coordinates L⁻¹η, with Ω = LLᵀ. Inside the ball that is the full Newton step when -H is positive definite; where -H is indefinite (a saddle or a non-concave region) the step follows the directions in which the density curves upward, out to the radius. The radius shrinks after a rejected step or a poor prediction and grows after a good step that reached it. A subject converges once gᵀ(-H)⁻¹g / 2 ≤ decrement_tol; the Newton step from there is taken as a final polishing step, so the returned mode is stationary to roundoff.

The Hessian blocks are the model's own (provides_eta_hessian), or sparse matrices computed from its batched gradients when it declares eta_hessian_sparsity. On a sparse block the trust-region step is found by sparse Cholesky factorizations of -H + νΩ⁻¹ (Moré & Sorensen 1983) instead of an eigendecomposition, so a subject with thousands of nested effects costs time and memory proportional to the Hessian's nonzeros.

source
NLMEEstimation.QuasiNewtonEBE Type
julia
QuasiNewtonEBE(; memory = 20, curvature_steps = 20)

Limited-memory BFGS per subject on η gradients, with backtracking (halving) to the Armijo condition. The inverse-Hessian approximation applies the last memory curvature pairs to the prior covariance Ω, rescaled at every update to the curvature last observed. A subject with n random effects therefore stores O(memory · n) numbers, and Ω is applied block by block for a RaggedNLMELayout. A subject converges once its standardized gradient ‖Lᵀg‖∞ ≤ gtol, with Ω = LLᵀ (the gradient with respect to the standardized random effects L⁻¹η), and the complete-data density is concave there.

BFGS keeps a positive-definite curvature model, so on its own it cannot follow a direction in which the density curves upward: a saddle point passes the gradient test, and next to one the steps along that direction stay tiny. The solver therefore checks the complete-data Hessian block where BFGS meets upward curvature (a curvature pair with sᵀy ≤ 0, which BFGS skips) and, once no subject is still iterating, at every subject that passed the gradient test. The block is sparse when the model declares eta_hessian_sparsity (two batched gradient calls per color of its pattern), else the model's own when it provides_eta_hessian (the one the result reports, so the check adds no model calls). Where -H is not positive definite, the next step is NewtonEBE's trust-region step with a radius of one prior standard deviation, halved until the density increases, and BFGS restarts from Ω.

A model with gradients only and no declared pattern is checked without a Hessian block: Lanczos on forward differences of batched gradients, at most min(neta, curvature_steps + 16) batched gradient calls per check, however many effects a subject has, and memory linear in them. A negative Ritz value proves upward curvature, and the next step goes one prior standard deviation along its Ritz vector. A subject of at most curvature_steps + 16 effects is checked exactly. Above that the check can miss upward curvature, so a converged subject is one where none was found, not one proven concave; declare eta_hessian_sparsity for an exact check. Likelihoods that are log-concave in η cannot have a saddle.

NLMEEstimation.EBEOptions Type
julia
EBEOptions(; maxiter = 200, decrement_tol = 1e-14, gtol = 1e-8, max_backtracks = 30,
           nonsmooth = true)

Settings of empirical_bayes.

  • maxiter: maximum number of iterations (accepted steps) per subject, and again for the search of a mode at a kink.

  • decrement_tol: NewtonEBE convergence, half the Newton decrement in log-density units.

  • gtol: QuasiNewtonEBE convergence, the standardized gradient ‖Lᵀg‖∞.

  • max_backtracks: maximum trust-region reductions (NewtonEBE) or step halvings (QuasiNewtonEBE) per iteration before a subject is reported as not converged (or, with nonsmooth, searched for a mode at a kink).

  • nonsmooth: search for, and certify, a mode on a kink of the complete-data log-density where the method finds no step that increases it (section "Modes at kinks" of empirical_bayes). With false such a subject is reported as not converged, as before NLMEEstimation 0.2.10.

NLMEEstimation.EBEResult Type
julia
EBEResult

Result of empirical_bayes. Column/entry k of every field belongs to subject subjects[k].

  • modes: neta × length(subjects) matrix of empirical Bayes estimates η̂_i.

  • hessians: the neta × neta Hessian in η of the complete-data log-density log p(y_i, η_i | θ, σ, Ω) at η̂_i per subject, or nothing when the model provides no second order (see ebe_covariances).

  • With a declared eta_hessian_sparsity, hessians holds SparseMatrixCSCs.

  • conditional_loglikelihood, complete_data_loglikelihood: the two log-densities at η̂_i.

  • converged, iterations: per-subject solver diagnostics.

  • gradient_norm: the standardized complete-data gradient ‖Lᵀg‖∞ at η̂_i.

  • nonsmooth: true where the mode is a certified mode on a kink of the complete-data log-density (section "Modes at kinks" of empirical_bayes), which has no gradient or curvature there. Its gradient_norm is then the standardized norm of the element nearest zero of the convex hull of the gradients sampled within 1e-6 prior standard deviations of the mode, and its hessians entry the Hessian the model reports at the mode, which is that of one smooth piece. Computations that need the curvature at the mode refuse such a subject with a NonsmoothModeError.

  • method: the EBEMethod used.

First-order conditional estimation ​

NLMEEstimation.focei Function
julia
focei(model, θ0, σ0, ω0; subjects = 1:nsubjects(model), free = nothing,
      options = FOCEOptions(), progress = nothing) -> FOCEResult

Estimate population parameters by minimizing the FOCE(I) OFV with NLopt's BOBYQA, a quadratic-interpolation trust-region algorithm. The model's θ and σ and the package's log-Cholesky ω are already unconstrained. Each objective call warm-starts subject EBEs from the preceding successful call. No population derivatives are taken. The FOCE curvature uses first η derivatives; the subject mode solver can also inspect η Hessians when the model supplies them. free may select one-based positions in the concatenated (θ, σ, ω) vector; other coordinates stay at their starting values. With a population prior, the outer objective is the MAP point's negative twice log posterior; the result still reports its likelihood separately. Covariance families declared by fixed_omega keep their fixed parts. The search covers the estimated standard deviations and correlation of a partially fixed family; a fully fixed family is not searched. free may not name a position inside a constrained family's ω segment. ω0 must hold the fixed values (apply_fixed_omega).

progress (a Treebars node or backend symbol) gets a FOCE(I) node counting objective calls against maxeval, with the best OFV so far as its message and each call's mode search as a transient child. Treebars.request_interrupt! on it stops the search at the current objective call and returns the best point so far, with converged = false and optimizer_info.status == :FORCED_STOP. An interrupt during the evaluation at θ0, σ0, ω0, before any search, raises Treebars.ProgressInterrupted.

NLMEEstimation.focei_evaluate Function
julia
focei_evaluate(model, θ, σ, ω; subjects = 1:nsubjects(model), η0 = nothing,
               interaction = true, ebe_method = QuasiNewtonEBE(),
               ebe_options = EBEOptions(), progress = nothing)

Evaluate the first-order conditional (with interaction by default) marginal log-likelihood. The EBEs maximize the exact complete-data log-density; their Laplace curvature uses only the first η derivatives of the Gaussian observation means and variances. Supply η0 as for empirical_bayes to warm-start the mode search; ebe_method and ebe_options configure it. A model's population_logprior, if present, is added once after the subject likelihood terms; it does not alter the subject EBEs. progress (a Treebars node or backend symbol) gets a FOCE(I) objective node with the mode search's node under it; an interrupt raises Treebars.ProgressInterrupted.

Stochastic approximation ​

NLMEEstimation.saem Function
julia
saem(model, θ0, σ0, ω0; rng=Random.default_rng(), subjects=nothing,
     η0=nothing, options=SAEMOptions(), kernel=StandardSAEMMH(),
     progress=nothing, integrated=integrated_families(model)) -> SAEMResult

Estimate population parameters using MCMC stochastic approximation. Subject chains persist across iterations. The Gaussian random-effect prior supplies a closed-form covariance M-step; MuReferencing also supplies the generalized-least-squares fixed-effect M-step. Remaining θ and σ coordinates use a first-order AD numerical M-step, which holds each chain's η fixed and so also moves the mu-referenced θ: a σ coordinate that trades off against a random effect then moves together with it. Its quasi-Newton search starts from a difference estimate of the objective's curvature, carried from one M-step to the next. By default, σ coordinates are updated online only when all structural θ coordinates have a MuReferencing sufficient-statistic update. Otherwise the update is :score: one Robbins–Monro step along the current draw's score per iteration (see SAEMOptions). numeric_mstep=:mixture selects the running conditional-density objective, which retains one latent-effect matrix per SA iteration and evaluates them all at every point of its search. Set numeric_mstep=:online to force an online update for undeclared structural θ as a model-specific approximation. SAEMResult.numeric_mstep records the selected mode. kernel selects the standard lockstep MH proposals, batched continuously adapted MALA proposals, or per-subject in-memory WarmupHMC NUTS transitions. When population_logprior is supplied, the M-step maximizes the same objectives plus the prior, added once. The mu-referenced θ and Ω move on from their closed-form update to the maximizer with the prior, a search that calls only the prior (one value and gradient per iteration) and moves along an omega_floor the data press against, and the numerical update of the remaining θ and σ includes the prior; so a prior adds no conditional-likelihood evaluations to the step. The model supplies a population-prior gradient or an AD backend from which to derive it. Covariance families declared by fixed_omega keep their fixed parts: a fully fixed family is not updated, and a partially fixed family maximizes the expected Gaussian random-effect density over its estimated standard deviations and correlation. ω0 must hold the fixed values (apply_fixed_omega); omega_floor applies to estimated parts only. A model rejects a point outside its domain by returning a log density of -Inf or by throwing a DomainError, OverflowError or PosDefException. The MH and MALA kernels then reject that subject's proposal alone, and the numerical and MAP M-steps halve their line-search step. The point each M-step starts from must evaluate finitely.

SAEMOptions(minibatch_size = b) moves only b randomly drawn subjects' chains per iteration and evaluates only those subjects in the numerical M-step (see SAEMOptions). That M-step screens only the batch's chains, so a chain drawn later can lie outside the model's domain at the population parameters of its next iteration; it is then replaced by a feasible draw from the random-effect prior. The progress message's Σ log p(y|η) is then the batch's sum scaled to all subjects.

integrated lists covariance families (for an NLMELayout, η blocks) whose random effects the model integrates out by its own Laplace approximation (see integrated_families for the methods it implements). The chains then sample only each subject's other random effects, against the Laplace conditional likelihood of the integrated ones, and a subject with none keeps no chain. After each iteration's transitions the model returns every subject's integrated modes û and covariance blocks C at its chain's state, and the M-step takes each integrated family's covariance and mu-referenced θ in closed form from those moments, E[u uᵀ] ≈ û ûᵀ + C, stochastically averaged like the chains' statistics; the numerical update of θ and σ maximizes the Laplace conditionals, holding the sampled effects fixed. Where the model is Gaussian in the integrated effects the moments are exact. With every family integrated nothing is sampled: the iterations are Laplace-EM, each taking the whole step (γ = 1) without mcmc_burnin, the burnin schedule or Ω annealing, and kernel is unused. Its fixed point is the maximum of the Laplace marginal likelihood where the likelihood is Gaussian in the effects, and close to it otherwise, because the closed-form covariance update leaves out the change of the Laplace curvature with the mode. The result's eta holds the sampled chains' states and the integrated modes. A later call can integrate another set, for example a staged fit that starts from Laplace-EM and then samples some families.

progress is a Treebars node (or a backend symbol such as :term) under which a SAEM node shows the run's phases: Pathfinder start (one subject per step), MCMC burn-in and Stochastic approximation, each counting its iterations. The running message gives the stage (M-step while it runs), the SA step size γ, the chains' summed conditional log-density at the current population estimate (MH and NUTS) and the kernel's acceptance, divergences or mean step size. Treebars.request_interrupt! on that node stops the run at the next iteration boundary: saem returns the estimate of the last completed iteration with interrupted = true and iterations counting the completed SA iterations.

NLMEEstimation.saem_population_gradient_style Function
julia
saem_population_gradient_style(model[, numeric_mode]) -> EvaluationStyle

Optional. Selects how SAEM computes the conditional-likelihood value and population-parameter gradient for its numerical M-step. Defaults to evaluation_style. A model with BatchedEvaluation can return PerSubjectEvaluation here when it implements an efficient conditional_loglikelihood_and_population_gradient for one subject; SAEM sums those subject values and gradients. Under BatchedEvaluation SAEM calls conditional_loglikelihood_sum_and_population_gradient for the whole batch instead. This choice affects only that M-step gradient (and LouisInformation's differences of it). Likelihood, η-gradient, and η-Hessian evaluation continue to use evaluation_style(model).

The optional second argument is Val(:online), Val(:score) or Val(:mixture), the resolved SAEM numerical M-step mode (minibatch SAEM passes Val(:online)). :online and :score evaluate one draw per objective (:online a search of up to numeric_maxiter gradients per M-step, :score about one gradient); :mixture evaluates every retained draw. Override it when one gradient route is efficient for single-draw updates but costly for the retained-draw mixture. By default every mode uses the one-argument style, preserving existing model methods.

NLMEEstimation.SAEMOptions Type
julia
SAEMOptions(; iterations=300, burnin=150, mcmc_burnin=20,
             mh_rounds=1, rw_scale=0.5, adapt_iterations=150,
             step_exponent=0.8, numeric_maxiter=12, mstep_interval=1,
             numeric_mstep=:auto,
             omega_floor=1e-8, omega_annealing=0.95,
             minibatch_size=nothing)

Settings for saem. The first burnin stochastic-approximation iterations use step size one; subsequent sizes are (k-burnin)^(-step_exponent). mcmc_burnin runs kernel sweeps at the starting population parameters without updating them. With StandardSAEMMH, each round makes one prior-independence and one joint random-walk proposal for every subject, then one random-walk proposal per η coordinate, each evaluated in one batch. The joint random-walk scale adapts toward 0.3 acceptance and each coordinate's scale toward 0.4 for the first adapt_iterations sweeps; then they are frozen. With WarmupHMCNUTS, each round makes one NUTS transition per subject with a kernel that adapts on every transition. omega_floor is a covariance eigenvalue floor in the M-step. With few subjects for the mu-referenced coefficients, the covariance that maximizes an M-step's Gaussian term can be singular; its closed-form update moves towards the floor by at most 100 coordinate updates per M-step, so Ω may approach it over several iterations. The fit also starts on the floor: an estimated part of ω0 below it by more than rounding is raised to it before the first sweep, with a warning naming the families, and fixed parts are kept. A start that holds the floor, such as a previous fit's estimate, is used as it is. A variance far below the floor, as a maximum a posteriori point that collapsed it leaves, gave the chains a target they could not sample: Pathfinder's start of a WarmupHMCNUTS chain drew points far below the start, the chains stayed there, and the first M-step took Ω from them. omega_annealing=0.95 anneals Ω while γ = 1, as Monolix and saemix do: an M-step may shrink no covariance family by more than that factor in any direction (its new Ω is at least omega_annealing times the previous one in the matrix order). Each such M-step sets Ω from one posterior draw per subject, so Ω wanders, and where it wanders towards a singular correlation, kernels whose proposals follow Ω cannot leave it. omega_annealing=0 turns it off and reproduces fits from before it was introduced. numeric_mstep=:auto uses an online update for remaining σ coordinates when all θ coordinates have a closed-form MuReferencing update; otherwise it uses :score. Every numerical update also moves the mu-referenced θ, holding each sampled η fixed. :online applies the online update to every remaining θ and σ coordinate: it optimizes the current complete-data conditional likelihood, then moves toward that optimizer by the SA step size, retaining one sampled latent-effect matrix. Its use for a structural θ without a declared sufficient statistic is an approximation. :score takes one Robbins–Monro step γ M ĝ per M-step along the score ĝ of the current draw's objective, with M its inverse curvature estimated from every subject's chain at M-steps 1, 2, 4, 8, … (the minibatch update below with every subject); numeric_maxiter is unused. An iteration then costs about one population gradient, and the estimates converge where the observed-data score vanishes, as :mixture's do. :mixture optimizes the exact running conditional-density mixture and retains every sampled matrix; its search evaluates every retained matrix, so the k-th SA iteration's M-step costs k times a one-draw search (:auto's choice for structural θ before NLMEEstimation 0.2.6). The default mstep_interval=1 updates population parameters every SA iteration; a larger interval is an approximate, lower-frequency variant in :online mode. With DualAveragingMALA, each round makes one batched MALA proposal and updates a separate subject step size throughout the run. Set mcmc_burnin=0 to omit a separate initial MCMC phase; burnin still controls the SA step sizes.

minibatch_size=nothing moves every subject's chain at every iteration. An integer b runs minibatch SAEM (Kuhn, Matias & Rebafka 2020): each SA iteration draws b of the n fitted subjects uniformly at random without replacement, and only their chains move. The mcmc_burnin sweeps still move every chain (and the first iteration does when mcmc_burnin = 0), so that each starts from its conditional posterior at the starting estimate; from chains left at their start, the first γ = 1 M-steps would shrink Ω, and with it every proposal scaled by Ω. The other subjects keep their last sampled latent effects, which stay in the stochastic-approximation statistics, so the Gaussian block uses every subject without evaluating the model. The numerical update evaluates the batch alone: each M-step takes one Robbins–Monro step min(γ, 4b/n) M ĝ along the batch's score ĝ, its conditional log density scaled to all n subjects. The cap limits a step to four times the batch's share of a Newton step, so one pass over the subjects nearly solves the update, as a full-batch search does, without the batch's whole sampling error. M is the inverse curvature of the full objective, estimated from every subject's chain at M-steps 1, 2, 4, 8, …. The step's mean is the full score, so the estimates converge to the same fixed point as full-batch SAEM, where a search to each batch's optimum would converge to a point biased by order 1/b. numeric_mstep must be :auto; the result reports :minibatch, and numeric_maxiter is unused. Each chain moves in only a fraction b / n of the iterations. b equal to n is the full-batch algorithm.

NLMEEstimation.SAEMResult Type
julia
SAEMResult

Population estimate from saem. eta holds the final subject-chain states, one column per entry of subjects. acceptance gives prior and joint random-walk and per-coordinate random-walk acceptance fractions (prior, random_walk, coordinates); rw_scale is the final joint proposal scale. These MH-only fields are missing for other kernels. kernel identifies the method and nuts_divergences counts its NUTS transitions that diverged. For MALA, mala_stepsizes and mala_acceptance hold per-subject final values; mala_adaptation_steps counts updates per subject, the fewest any subject received under minibatch_size. The acceptance fractions are over every subject's proposals, so under minibatch_size over the batches'. numeric_mstep records the resolved numerical M-step mode (:online, :score or :mixture, :minibatch under minibatch_size). objective is :ML without a model population prior and :MAP otherwise. The result is a population point estimate, not a draw from a population posterior. iterations counts the completed SA iterations; interrupted is true when a Treebars interrupt request (see progress in saem) stopped the run before SAEMOptions.iterations, so the estimate is that of the last completed iteration. The acceptance and MALA fields are NaN when no kernel sweep ran. integrated lists the families the model integrated by its own Laplace approximation (integrated in saem); their entries of eta are the Laplace modes at the final state, and kernel is :laplace_em when every family was integrated, so that nothing was sampled.

NLMEEstimation.RaggedSAEMResult Type

RaggedSAEMResult

SAEM estimate for a RaggedNLMELayout. eta[k] is subject subjects[k]'s compact latent vector. omega_matrix[f] is the shared covariance of random-effect family f. The other fields are those of SAEMResult: acceptance and rw_scale for the MH kernel, whose per-coordinate acceptance is per family coordinate, nuts_divergences for NUTS, the mala_ fields for MALA, objective (:MAP with a population prior, :ML without one), iterations, interrupted and integrated.

NLMEEstimation.StandardSAEMMH Type
julia
StandardSAEMMH()

The standard SAEM per-subject kernel: per subject and MH round, one prior-independence proposal, one covariance-scaled random-walk Metropolis proposal, and one random-walk proposal per η coordinate, each coordinate with its own adapted scale (saemix's componentwise kernel). The coordinate sweep keeps a subject's chain moving when its posterior widths differ widely across coordinates, which a single joint scale cannot follow.

NLMEEstimation.WarmupHMCNUTS Type
julia
WarmupHMCNUTS(; target_acceptance_rate=0.8, max_tree_depth=10, threads=false)

One continuously adapting NUTS chain per subject, WarmupHMC's ContinuousNUTSState. Pathfinder from the subject's starting η at the starting population parameters gives the first position and the first diagonal metric, and every transition then adapts the metric and the step size from its leapfrog leaves, for the whole fit, as θ, σ and Ω move. There is no warmup phase and no η Hessian. target_acceptance_rate must lie strictly between zero and one.

threads = true runs each subject's chain in its own task on Julia's threads (start Julia with -t <n>), for the call this kernel is passed to, Pathfinder start included. With the same seed and inputs, the fit equals the one threads = false gives bit for bit when both routes return bit-identical model values and gradients at every queried point. Equality only at the starting point is insufficient: roundoff differences can change Pathfinder's path and subsequent NUTS draws. Each chain makes its own one-subject model calls, whatever evaluation_style the model declares, so the model is called concurrently for different subjects. Passing threads = true states that it can be: check_protocol(...; threads = true) tries that out. With a model that declares Enzyme as its ad_backend, saem and covariance_step refuse an Enzyme without the repair for reverse gradients beside allocating threads, because they can be silently wrong there. On a process with one thread the chains run one after another, with a warning.

With threads = false a PerSubjectEvaluation model's chains run one after another and a BatchedEvaluation model's in lockstep, one batched call per leapfrog step. A batched model pays for one-subject calls under threads = true, so that can be much slower than lockstep where such a call costs a whole-model sweep.

NLMEEstimation.DualAveragingMALA Type
julia
DualAveragingMALA(; metric=:prior, initial_stepsize=0.1,
                    target_acceptance_rate=0.574,
                    gamma=0.05, t0=10.0,
                    min_stepsize=1e-5, max_stepsize=10.0,
                    curvature_floor=1e-4)

MALA with one independent dual-averaging step size per subject. metric=:prior uses the current Ω as proposal covariance. metric=:hessian obtains a fixed per-subject covariance from the initial regularized local posterior Hessian, falling back to Ω if the model has no Hessian. That fallback stays the starting Ω: when a variance component then shrinks, the step size shrinks with its posterior, and the chains can stop moving. Gradients are evaluated in subject batches. The source gradient is reused after each accept or reject until a population M-step changes the target. Adaptation continues at every transition, including during population updates. This changing-target, continuously adapted mode is experimental; its transition is Metropolis corrected at each fixed population state, but a full SAEM convergence guarantee is not implied.
