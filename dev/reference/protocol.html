NLMEEstimation.EvaluationStyle Type
julia
EvaluationStyle

How a model evaluates its conditional log-density, declared by evaluation_style:

  • PerSubjectEvaluation (default): the model implements conditional_loglikelihood for one subject at a time.

  • BatchedEvaluation: the model implements conditional_loglikelihoods for a batch of subjects in one pass, as joint-program backends (one log-density over all subjects) do.

source
NLMEEstimation.PerSubjectEvaluation Type
julia
PerSubjectEvaluation()

The model evaluates one subject per call: it implements conditional_loglikelihood. Batched entry points loop over subjects.

source
NLMEEstimation.BatchedEvaluation Type
julia
BatchedEvaluation()

The model evaluates a batch of subjects per call: it implements conditional_loglikelihoods. Per-subject entry points evaluate a batch of one; derivatives of a batch come from AD of the batch's summed log-density, which yields every subject's η-gradient at once because subjects are conditionally independent.

source
NLMEEstimation.evaluation_style Function
julia
evaluation_style(model) -> EvaluationStyle

Optional. Defaults to PerSubjectEvaluation.

source
NLMEEstimation.conditional_loglikelihood Function
julia
conditional_loglikelihood(model, i, θ, σ, η) -> Real

The conditional log-density log p(y_i | θ, σ, η_i) of subject i's observations, without the random-effect prior (which this package owns, see re_logprior). θ and σ are in the model's unconstrained coordinates.

Required under PerSubjectEvaluation; derived from conditional_loglikelihoods under BatchedEvaluation.

Return -Inf where the density is zero (a failed solve, for example); estimators treat non-finite values as infeasible and report them, never as success.

source
NLMEEstimation.conditional_loglikelihoods Function
julia
conditional_loglikelihoods(model, subjects, θ, σ, H) -> Vector

The conditional log-densities of a batch of subjects: entry k is log p(y_i | θ, σ, η_i) for i = subjects[k] and η_i = H[:, k], with H of size neta × length(subjects) for NLMELayout. For RaggedNLMELayout, H[k] has length neta(layout, subjects[k]).

Required under BatchedEvaluation: a joint-program model places each column of H into its subject's random-effect slots (the other subjects' slots are irrelevant, by conditional independence) and returns the per-subject terms. Derived from conditional_loglikelihood under PerSubjectEvaluation.

source

NLMEEstimation.conditional_loglikelihood_sum_and_population_gradient Function
julia
conditional_loglikelihood_sum_and_population_gradient(model, subjects, θ, σ, H) -> (ℓ, ∇θ ℓ, ∇σ ℓ)

Optional, or provided by ad_backend. The conditional log-density of the batch subjects, which is the sum of its subjects' conditional log-densities (a real number, not one value per subject), with its gradients in θ and σ at fixed H. H is in the batch shape of conditional_loglikelihoods. It is the batched counterpart of conditional_loglikelihood_and_population_gradient, with the same return triple.

SAEM's numerical M-step and LouisInformation call it whenever saem_population_gradient_style returns BatchedEvaluation. Each value and gradient of the M-step's objective then costs one call per retained draw, over the M-step's subjects (every fitted subject, or the minibatch). Under PerSubjectEvaluation they sum conditional_loglikelihood_and_population_gradient instead.

The default differentiates the sum of conditional_loglikelihoods with ad_backend(model). A model implements this method when it computes the gradient more cheaply itself, or when its batched program should not be handed to the backend as a whole. A wrapper that forwards the protocol to an inner model (to count, time or cache its calls) forwards this method like the others, so that the wrapped fit takes the inner model's route.

source
NLMEEstimation.ad_backend Function
julia
ad_backend(model) -> Union{Nothing, ADTypes.AbstractADType}

Optional. The automatic-differentiation backend this package uses, through DifferentiationInterface, for every derivative method the model does not implement itself. The default nothing declares no backend; calling a missing derivative method is then an error.

What this package promises and tests is reverse-mode AD with Enzyme, ADTypes.AutoEnzyme(); second-order defaults are forward-over-reverse Hessian-vector products. Other backends are passed through untested.

source

Optional. The backend used for default second-order derivatives (η Hessian blocks). Defaults to ad_backend. Return nothing to declare that the model provides no second order, so estimators use their gradient-only paths.

NLMEEstimation.provides_eta_hessian Function
julia
provides_eta_hessian(model) -> Bool

Optional. Whether η Hessian blocks are available (conditional_loglikelihood_hessian_blocks). Defaults to whether a hessian_ad_backend is declared; a model implementing the Hessian methods itself returns true. Second order is only ever requested as per-subject neta × neta blocks, never as a joint matrix.

source
NLMEEstimation.eta_hessian_sparsity Function
julia
eta_hessian_sparsity(model, i) -> Union{Nothing, AbstractMatrix{Bool}}

Optional. Which entries of subject i's conditional η Hessian ∇²η ℓ_i can be nonzero: an n × n Boolean matrix, usually a SparseMatrixCSC{Bool}, with n = neta(nlme_layout(model), i). Entry (j, k) is true when η_j and η_k can enter the same observation's likelihood. The default nothing declares nothing, and the Hessian is treated as dense. A model declares a pattern for every subject or for none.

With a pattern, the estimators compute the subject's η Hessian as a sparse matrix from a few batched gradient evaluations, one pair per color of a star coloring of the pattern (central differences of conditional_loglikelihoods_and_gradients), and factor it sparsely. A subject of nested random effects, whose units interact only through the effects above them, then costs memory and time linear in its number of effects; dense Hessian blocks cost their square. empirical_bayes uses NewtonEBE by default for such a model, its result's hessians are sparse, and marginal_loglikelihood and covariance_step take their curvature from them. The pattern supersedes conditional_loglikelihood_hessian_blocks: a model that declares one is not asked for dense blocks. check_protocol checks a declared pattern against Hessian-vector products along random directions.

The diagonal and symmetry are implied: P .| P' .| I is used.

Population priors ​

NLMEEstimation.population_logprior Function
julia
population_logprior(model, θ, σ, ω) -> Union{Nothing, Real}

Optional log prior on the population coordinates, evaluated once per objective evaluation, not once per subject or retained SAEM draw. Return nothing (the default) for maximum likelihood. A model with a prior returns its log density with respect to the unconstrained (θ, σ, ω) coordinates. If the original prior is defined on transformed parameters, the model must include the transformation's log absolute Jacobian here. ω is the package's log-Cholesky coordinate vector. The random-effect prior η ~ N(0, Ω) is already owned by this package and must not be repeated here.

Optional gradient for a model's population_logprior. The default uses ad_backend(model) when a prior is present and returns zero gradients when there is none. Models may implement this method directly, including when their conditional-likelihood gradient uses a different backend.

NLMEEstimation.mu_referencing Function
julia
mu_referencing(model) -> Union{Nothing, MuReferencing}

Optional trait. Declares which θ coordinates enter the model as typical values of the random effects, ϕ_i = X_i θ_μ + η_i. SAEM's closed-form M-step needs it. Default: nothing (not declared).

source
NLMEEstimation.MuReferencing Type
julia
MuReferencing(theta_indices, design)

Mu-referencing declaration (see mu_referencing).

  • theta_indices: the θ coordinates that are mu-referenced.

  • design: one neta × length(theta_indices) matrix X_i per subject.

Contract: for every subject i, conditional_loglikelihood depends on θ[theta_indices] and η only through the individual linear predictor ϕ_i = X_i * θ[theta_indices] + η. Equivalently, it is unchanged under θ[theta_indices] .+= δ, η .-= X_i * δ. The model applies its own inverse link to ϕ_i. A zero row of X_i marks an η component without a mu-referenced typical value.

source
NLMEEstimation.laplace_marginals_and_gradient Function
julia
laplace_marginals_and_gradient(model, subjects, θ, σ, ω, H) -> (ℓ, ∇θ, ∇σ, ∇ω)

Optional. The Laplace approximation of each listed subject's marginal log-likelihood, and the gradient of their sum. Entry k of ℓ is

julia
log p(y_i, η̂_i | θ, σ, ω) + d_i/2 log 2π - 1/2 log det(-H_i)

for i = subjects[k], with d_i random effects, η̂_i the mode of the complete-data log-density at (θ, σ, ω) and H_i its η Hessian there, the value AdaptiveGaussHermite(nodes = 1) computes. ∇θ, ∇σ and ∇ω are the gradients of sum(ℓ) in the full θ, σ and ω, with the mode's dependence on them included (the implicit-function theorem), so they are third-order quantities. A model with a population_logprior leaves it out here.

H holds starting points for the mode search, in the batch shape of conditional_loglikelihoods. It is the same batch at every call of a covariance_step, so a warm-started search stays a smooth function of the coordinates. A summed gradient is asked for because a joint program gets it in one pass, where one gradient per subject would cost one pass per subject.

With provides_laplace_gradient, a covariance_step with AdaptiveGaussHermite(nodes = 1) calls only this method and the population prior: 2p + 1 calls for p coordinates, with no mode search and no conditional evaluation of its own. check_protocol compares its values with the package's Laplace approximation and its gradient with a central difference. Where a subject's complete-data density has several local modes, η̂_i is the one the model's search reaches from H, and check_protocol compares at it when the model reports its modes through laplace_conditional_moments with every family integrated; without that method the package's search starts from the checked η, and can end at another mode.

It is laplace_conditionals_and_population_gradient with every family integrated, which is the default: a model that implements that method only needs to declare provides_laplace_gradient.

source
NLMEEstimation.integrated_families Function
julia
integrated_families(model) -> Vector{Int}

Optional. The covariance families whose random effects the model integrates out by its own Laplace approximation when saem fits it: the families of a RaggedNLMELayout, or the eta_blocks of an NLMELayout, by index. Defaults to none. saem(...; integrated = …) chooses another set for one fit, so a staged fit can integrate different families in successive calls.

A model that integrates families implements laplace_conditionals_and_gradients, laplace_conditional_moments and laplace_conditionals_and_population_gradient for every set it is asked to integrate. Each takes the set as its second argument, a sorted vector of family indices, and a batch H in the shape of conditional_loglikelihoods: in each subject's column the entries of the integrated families' instances are starting points for the mode search, and the other entries, the sampled ones, are given.

source
NLMEEstimation.laplace_conditionals Function
julia
laplace_conditionals(model, integrated, subjects, θ, σ, ω, H) -> ℓ

Optional. The values of laplace_conditionals_and_gradients alone, for proposals that need no gradient. Defaults to computing both; implement it where a value costs less than a gradient.

source
NLMEEstimation.laplace_conditionals_and_gradients Function
julia
laplace_conditionals_and_gradients(model, integrated, subjects, θ, σ, ω, H) -> (ℓ, G)

Required to sample with integrated_families. Entry k of ℓ is the Laplace approximation of subject i = subjects[k]'s conditional log-likelihood given its sampled random effects s, with the instances u of the families in integrated integrated out:

julia
log p(y_i | s, û) + log p(û | Ω) + d/2 log 2π - 1/2 log det(-H_uu)

with d integrated effects, û the mode of log p(y_i | s, u) + log p(u | Ω) in u and H_uu its Hessian there. p(u | Ω) is the package's Gaussian prior of those instances at ω, so the value depends on ω; the sampled effects' prior is left out, as in conditional_loglikelihoods. With nothing integrated it is the conditional log-likelihood. G has the shape of H: the gradient of ℓ[k] in the sampled entries of column k, with the mode's dependence on them included, and zero in the integrated entries, which only start the mode search.

SAEM's chains sample the sampled entries against ℓ plus their prior, so a mode search warm-started from H must make ℓ a smooth function of them.

source
NLMEEstimation.laplace_conditional_moments Function
julia
laplace_conditional_moments(model, integrated, subjects, θ, σ, ω, H) -> (ℓ, M, C)

Required with integrated_families. The values ℓ of laplace_conditionals and the Gaussian (Laplace) approximation of each subject's integrated effects given its sampled ones. M has the shape of H, its integrated entries at the mode û and its sampled entries those of H. C[k] lists one covariance matrix per integrated family instance of subject subjects[k], in η order: the instance's diagonal block of (-H_uu)⁻¹, the covariance of the approximation. SAEM's M-step takes each integrated family's covariance from these moments, E[u uᵀ] ≈ û ûᵀ + C, so only the diagonal blocks are needed, never the whole inverse.

source
NLMEEstimation.laplace_conditionals_and_population_gradient Function
julia
laplace_conditionals_and_population_gradient(model, integrated, subjects, θ, σ, ω, H) -> (ℓ, ∇θ, ∇σ, ∇ω)

Required with integrated_families when SAEM's numerical M-step runs (the model has σ coordinates or θ coordinates without a closed-form MuReferencing update). The values ℓ of laplace_conditionals and the gradients of sum(ℓ) in θ, σ and ω at fixed sampled effects, with the mode's dependence on them included. With every family integrated it is laplace_marginals_and_gradient.

Conformance ​

NLMEEstimation.check_protocol Function
julia
check_protocol(model, θ, σ, ω; subjects = 1:nsubjects(model), η = nothing,
               reference_backend = nothing, reference_hessian_backend = reference_backend,
               population_gradient = false, rtol = 1e-8,
               integrated = integrated_families(model), threads = false) -> true

Check that model implements the protocol consistently at the given parameters, and throw a ProtocolViolation naming the first violation otherwise.

Checked for the batch subjects at random effects η (zeros by default; a neta × length(subjects) matrix, one vector for all subjects, or one vector per subject):

  • the layout matches the lengths of θ, σ and ω, and evaluation_style is an EvaluationStyle;

  • the batched log-densities are finite reals and equal the per-subject ones;

  • the batched gradients equal the per-subject gradients, and the values returned alongside derivatives equal the plain values;

  • subjects are separable: changing one subject's η leaves every other subject's log-density unchanged;

  • when provides_eta_hessian: the Hessian blocks are square, symmetric and equal the per-subject Hessians;

  • a declared eta_hessian_sparsity pattern exists for every checked subject, has its size, and covers every nonzero entry of the η Hessian: the sparse Hessian recovered from it, times a random direction, equals the Hessian-vector product along that direction (central differences of the batched gradients, within max(rtol, 1e-5));

  • a declared mu_referencing trait has one design per subject of the right size, and the density is invariant under the mu-referencing shift;

  • a declared observation_model reproduces the conditional log-density.

  • a declared Gaussian model's batched moments and first-order η Jacobians have the promised per-subject shape and agree with its plain moments;

  • a declared fixed_omega is valid for the layout, and ω holds its fixed values;

  • with provides_laplace_gradient: laplace_marginals_and_gradient returns one value per subject and gradients of the lengths of θ, σ and ω, its values equal marginal_loglikelihood with AdaptiveGaussHermite(nodes = 1) (within max(rtol, 1e-6)), and its gradient along a random direction equals a central difference of its values (within max(rtol, 1e-5)). A subject's complete-data density can have several local modes, each with its own Laplace value, so the reference is taken at the model's own modes where the model implements laplace_conditional_moments for every family integrated: its values must equal the hook's, and its modes must be modes (the package's search from them stays within max(rtol, 1e-5)). Otherwise the reference starts its search from η;

  • with integrated families (by default integrated_families): laplace_conditionals_and_gradients, laplace_conditionals and laplace_conditional_moments agree in their values and shapes; the values, modes and covariance blocks equal the package's own Laplace approximation of the integrated effects given the others (within max(rtol, 1e-6) for values and max(rtol, 1e-5) for modes and covariances; a dense check meant for small subjects); the gradient is zero in the integrated entries and, along a random direction of the sampled ones, equals a central difference of the values; and where SAEM's numerical M-step would run, laplace_conditionals_and_population_gradient agrees with the values and with a central difference along a random direction of θ, σ and ω.

With reference_backend (an AD backend), the model's η gradients are also compared against that backend, and its Hessian blocks (when provided) against reference_hessian_backend (for Enzyme, a forward-over-reverse DifferentiationInterface.SecondOrder). With population_gradient = true, the optional θ/σ gradient is checked as well (against reference_backend when given). Where saem_population_gradient_style returns BatchedEvaluation for some numerical M-step mode, conditional_loglikelihood_sum_and_population_gradient on the checked batch must then return a real value and gradients of the lengths of θ and σ that equal the sums of the per-subject values and gradients.

With threads = true, which needs a Julia process with several threads, all subjects are evaluated at once on Julia's threads, 20 times over, and every value and η gradient must equal its one-at-a-time result. That tries out what WarmupHMCNUTS(threads = true) asks of a model. A pass is evidence, not proof: a race shows only if it happens during these calls.
